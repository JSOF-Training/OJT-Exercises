1. You can override the field `addr_limit` to grant your process access to the kernel address space by bypassing the check in `copy_to_user`/`copy_from_user`. Then suppose you want to **read** from a kernel address, then you can simply execute a **write** syscall in your C tool (which will call `copy_from_user`) to any file with the buffer argument being a kernel address. You'd then get the contents of the kernel's memory in that file. Similarly, you can execute a **read** syscall which will call `copy_to_user` thus **writing** to a user-controlled kernel address. Read more [here](https://blog.lexfo.fr/cve-2017-11176-linux-kernel-exploitation-part4.html#core-concepts-4).
2. Or you can call `mmap` to allocate yourself a new page, then change the `pfn` of that page in your process' page table to any other pfn, for example you might choose the pfn of the page table itself. This way, if you `mmap` two pages, remap the first to your page table using the driver, then you can remap the second one in user mode without calling the driver. Thus giving you a stable R/W primitive into the kernel without requiring any syscalls. Tip: make sure you know exactly your CPU model and in which mode it operates because the page tables can change depending on the CPU and mode (within ARM).
